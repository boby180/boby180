# photo_sync: השוואת תמונות בין המחשב לשרת Synology

הכלי סורק את התמונות במחשב ובשרת, משווה ביניהן ומעלה לשרת את מה שחסר.

## איך משווים תמונות

לכל תמונה נאספים שלושה סוגי מידע:

| שכבה | מה נבדק | למה זה חשוב |
|------|---------|-------------|
| קובץ | שם, גודל, תאריך שינוי | זיהוי מהיר |
| תוכן | **SHA-256**, טביעת אצבע של הקובץ (עותק זהה לגמרי) ו-**pHash**, טביעת אצבע חזותית של התמונה | מזהה את אותה תמונה גם אם שונה לה השם, הגודל, הדחיסה או הסיבוב |
| תיאור (מטא-דאטה) | תאריך צילום, מצלמה, מידות, כותרת, **תיאור** ומילות מפתח (EXIF/XMP) | מבדיל בין תמונות דומות מאוד (צילום רצף) ומראה אם התיאור שונה בין המחשב לשרת |

כל תמונה במחשב מקבלת אחד מהסטטוסים האלה:

* **קיים בשרת (זהה)**: יש בשרת עותק זהה לגמרי, גם אם בשם אחר או בתיקייה אחרת.
* **קיים בשרת (דומה)**: בשרת יש את אותה תמונה (מוקטנת, דחוסה מחדש, או עם תיאור שעודכן). היא לא תועלה, וההבדלים (למשל `description: ים != חוף`) יופיעו בדוח.
* **חסר בשרת**: לא נמצאה התאמה, ולכן התמונה תועלה.

תמונות שהמראה שלהן דומה אבל תאריך הצילום, המצלמה או יחס הגובה-רוחב שלהן שונים נחשבות לתמונות שונות, ולכן יועלו.

## התקנה והרצה ב-Windows (הדרך הפשוטה)

1. חלץ את הקבצים לתיקייה `C:\PhotoSync`.
2. לחץ פעמיים על `run.bat`.
   בפעם הראשונה הוא מוצא את Python שמותקן במחשב (כולל Anaconda) ומתקין את הספריות.
   אם Python לא נמצא, פתח את Anaconda Prompt והרץ ממנו את `run.bat`, או התקן Python מ-python.org
   (בהתקנה סמן "Add python.exe to PATH").
3. בתפריט שנפתח בוחרים מספר: בדיקת הגדרות, השוואה (הדוח נפתח לבד), הרצת ניסיון, העלאה בפועל.

## התקנה ידנית

```bash
pip install -r requirements.txt
pip install -r requirements-optional.txt   # תמיכה בתמונות HEIC של אייפון
```

## הגדרה: כאן מכניסים את הכתובות

```bash
cp config.example.yaml config.yaml      # ב-Windows: copy config.example.yaml config.yaml
```

ערוך את `config.yaml`:

* `local.paths`: תיקיות התמונות במחשב, למשל `C:/Users/me/Pictures`.
* `server.paths`: התיקיות בשרת להשוואה. אפשר לרשום כמה תיקיות, למשל `//DS920/photo` ו-`//DS920/home/Photos`.
  כונן ממופה (כמו `Z:`) מצביע על תיקייה משותפת אחת בלבד. כדי לראות לאן הוא מצביע, הרץ `net use`.
* `server.upload_path`: לאן להעלות את התמונות החסרות. גם התיקייה הזו נכללת בהשוואה.

ההעלאה הרגילה (`copy`) מעתיקה דרך הכונן הממופה. אפשר גם להעלות דרך ה-API של File Station
(`upload_method: filestation`). במקרה כזה הסיסמה נקראת ממשתנה סביבה ולא נשמרת בקובץ:

```bash
set SYNOLOGY_PASSWORD=...          # Windows
export SYNOLOGY_PASSWORD=...       # Mac/Linux
```

גם במצב `filestation` צריך ש-`server.paths` יהיו נגישים, כי הסריקה של השרת נעשית דרכם.

## שימוש

```bash
python -m photo_sync check                # בדיקת הגדרות וגישה לתיקיות
python -m photo_sync compare              # השוואה, יוצר דוח HTML ו-CSV בתיקייה reports/
python -m photo_sync upload               # הרצת ניסיון: מציג מה יועלה, בלי להעלות
python -m photo_sync upload --execute     # העלאה בפועל
```

### גרסה טובה יותר במחשב

לפעמים בשרת יש רק עותק דחוס או מוקטן של תמונה (למשל עותק מ-Google Photos), ובמחשב יש את המקור.
בדוח, העמודה "איכות טובה יותר" מראה איפה הגרסה הטובה. כדי להעלות גם את הגרסאות האלה:

```bash
python -m photo_sync upload --include-better             # הרצת ניסיון
python -m photo_sync upload --include-better --execute   # העלאה בפועל
```

העותק הקיים בשרת לא נמחק. אחר כך אפשר למצוא אותו עם `duplicates`.

## תמונות כפולות

```bash
python -m photo_sync duplicates                  # כפילויות בשרת (ברירת המחדל)
python -m photo_sync duplicates --where computer # כפילויות במחשב
python -m photo_sync duplicates --where all      # גם וגם
```

הפקודה רק יוצרת דוח ולא מוחקת כלום. היא מוצאת שני סוגים:

* **עותק זהה**: אותו קובץ בדיוק שמור בכמה מקומות. הדוח מראה כמה מקום אפשר לפנות.
* **אותה תמונה בגרסה אחרת**: גרסה מוקטנת או דחוסה של אותה תמונה. צילומי רצף (זמן צילום שונה) לא נחשבים כפולים.

בכל קבוצה מסומנת הגרסה שמומלץ להשאיר: זו עם הרזולוציה הגבוהה ביותר.
תוצאות הסריקה נשמרות, כך שאחרי `compare` הפקודה רצה מהר.

## בטיחות

* קובץ קיים בשרת **אף פעם לא נדרס**. אם השם תפוס, נוסף לו מספר, למשל `IMG_1 (1).jpg`.
* ברירת המחדל של `upload` היא הרצת ניסיון, וההעלאה מתבצעת רק עם `--execute`.
* כפילויות במחשב מועלות פעם אחת בלבד.
* תיקיות המערכת של סינולוגי (`@eaDir` עם התמונות הממוזערות, `#recycle`) לא נכללות בהשוואה.
* תוצאות הסריקה נשמרות ב-cache, כך שסריקה חוזרת של השרת מהירה ובודקת רק קבצים חדשים או ששונו.
